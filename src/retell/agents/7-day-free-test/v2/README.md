# Free-Test Capture And Handoff V2 Candidate

This directory contains a public, provider-neutral, source-only acceptance candidate for `call_gap_capture_handoff_v2`. It is not a Retell export, an import package, a runtime mapping, deployment evidence, or authorization to change an agent, number, route, call, notification, or customer system.

The Retell source status is `NOT_READY`; the capability profile remains deliberately `draft`, disabled, unwired, non-importable, and unbound to traffic. Read-only Retell schema and documentation reviewed on 2026-08-25 confirm the required `transfer_call` node fields, predefined destination shape, warm-transfer configuration fields, exact `Transfer failed` edge prompt, and the canonical `transfer_started`, `transfer_bridged`, `transfer_cancelled`, and `transfer_ended` webhook events. Exact sanitized live raw-event fixtures, provider readback, Draft import evidence, and behavioral acceptance are still absent, so source completeness is not claimed.

The source-only gateway parser accepts only those four event names with an exact top-level envelope. It requires an injected private HMAC-SHA256 key represented by an exact 32-byte Buffer. Each installation must generate the key at install time from a cryptographically secure random source with 256 bits of entropy; public, deterministic, password-derived, or other low-entropy derivation is prohibited. The key is never retained, returned, or logged. Separate HMAC domains protect destination fingerprints, authorized transfer-configuration fingerprints, event claim keys, and a binding-scoped key-verification tag. The tag makes a wrong rotated key fail closed even for `transfer_ended`, whose webhook has no destination. Public destination dictionaries cannot reproduce the keyed identifiers. Provider call, agent, client, deployment, configuration version, destination, and minimized transfer configuration are checked against one immutable verified binding. Every normalized event, including `transfer_ended`, carries the verified `transfer_configuration_fingerprint` so the durable call ledger rejects cross-request configuration rebinding before claim or notification mutation.

The contract keeps two schemas distinct: Draft transfer configuration uses the confirmed snake_case fields, while webhook transfer evidence uses the documented camelCase payload fields. The webhook `transfer_option` is an exact allowlist: every unknown field fails closed until exact sanitized live fixtures and a reviewed contract update establish its semantics. Snake_case and security-configuration aliases, including `optOutHumanDetection`, also fail closed. Unknown camelCase fields such as `transferRingDurationMs` are rejected rather than inferred. Retell's nested full-call object remains variable; its unknown fields are bounded and discarded without being persisted, returned, fingerprinted as security evidence, or used to infer behavior.

The parser rejects unsupported casing, malformed or oversized evidence, non-E.164 targets, target or transfer-configuration rebinding, forbidden security aliases, unknown transfer-option fields, and unknown top-level fields. It never retains the raw call, destination, transfer option, transcript, prompt, number, or HMAC key, and it never infers `transfer_failed` or a failure subtype from cancellation or ending. It is not imported by the active gateway, is not represented as an importable Retell configuration, and has no traffic binding. Draft import/readback, webhook authentication and delivery integration, exact sanitized raw-event fixtures, and behavioral acceptance remain required before runtime wiring.

The current `call_gap_monitor_v1` files outside this directory remain the rollback boundary and are not modified by this candidate.

## Offline validation

```powershell
python src\retell\agents\7-day-free-test\v2\tools\validate_candidate.py
python -m unittest tools.safety.tests.test_retell_v2_handoff_candidate -v
```

Both commands are deterministic and prohibit network access. The gateway package test suite also exercises the strict Retell event parser directly. A passing local result proves only the public acceptance contract, parser minimization and fail-closed validation, 100 synthetic scenarios, order-independent monotone transfer-state convergence, authoritative evidence gates, required durable-ledger/notification-store interface behavior, irreversible payload-null suppression for sensitive/nonactionable outcomes, notification idempotency, isolation rules, and mutation coverage. The candidate supplies no live storage, delivery, route, webhook ingress, or active provider adapter. Retell Draft readback/import, text or voice simulation, human detection, voicemail detection, webhook authentication and delivery, number binding, route activation, and email delivery remain deferred live work requiring separate approval.
