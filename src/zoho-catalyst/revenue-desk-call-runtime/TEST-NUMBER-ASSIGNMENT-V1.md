# Protected per-test number assignment

Approved design: each simultaneous free test uses a distinct Sylvara-owned destination number. This source adds assignment controls; it purchases nothing and proves no live forwarding or provider binding.

The default `RETELL_NUMBER_ASSIGNMENT_MODE=qa_only` preserves the accepted single QA number. `approved_inventory` requires that QA number to remain explicitly configured and excluded from all inventory entries. It also requires protected `RETELL_NUMBER_INVENTORY_JSON` and its exact UTF-8 SHA-256 pin. None of these variables enables `RETELL_ROUTE_MODE`, admission or calling.

The private document has exactly `schemaVersion` (1), `environment` (`development`), `sourceRevision`, `operatorIdHash`, `approvalSha256` (the independently approved inventory document reference) and `assignments`. Each entry has exactly `dealId`, `journeyId`, `clientId`, `deploymentId`, `phoneNumber`. Bind these to authoritative native CRM lineage and the existing deterministic deployment identity. The operator must reconcile purchased/imported inventory and approved ownership before installing the protected document. Caller input, Forms, mutable CRM number fields and shared agent identity are never inventory authority. Do not commit populated documents or real phone numbers.

The Controller loader verifies source/operator/environment, document pin, exact field types, US number shape, duplicate numbers/deployments/Deal-Journey pairs, and the QA reservation. Staging checks the exact full tuple before durable effects. Activation requires both the protected selection and matching current CRM test-number projection, followed by existing exclusive-owner and live-route evidence. The provider selects only that assignment; unknown or conflicting assignment fails before dispatch. The existing isolated-test nickname, agent/version, endpoint, SMS/outbound and rollback checks remain intact. This does not enable prospect/customer routing or replace later provider acceptance.

`RevenueDeskDeployments.NUMBER_LOOKUP_HASH` remains globally unique. Retain deployment rows after stop; never delete a reservation or reuse its number. Changing or removing the protected inventory cannot erase durable ownership. The historical inactive-successor operation changes a number hash and is held in inventory mode, before reads/writes. No initial number replacement/recycling path is introduced. Removing an inventory entry is containment, not a release of historical ownership; it can cause manual rollback to be required, so reconcile restoration before changing an active assignment.

Runtime tenant resolution still uses the authenticated destination number and durable deployment/call lineage. Agent IDs and caller numbers are not tenant keys. No changes to event schemas, late-event settlement, seven-day/25-call limits or immutable configuration approval.

Offline acceptance covers two simultaneous exact assignments, zero-effect replay, signed-but-unassigned number/client/Deal/Journey attempts, duplicate inventory, stale source/operator, bad pin, QA conflict, retained stopped ownership, shared-agent destination selection, unmapped pre-dispatch holds, exact isolated-number rollback and historical successor denial. Existing tenant-negative event acceptance is reused unchanged.

Live prerequisites remain separate: approved purchased inventory and exact per-test configuration; supported fixed principal and private configuration permissions; independently verified actual forwarding/agent/version/endpoint/coverage/fallback; bounded authorized internal Retell acceptance and restore checks. No purchases, new access grants, provider invocations or calls are authorized by these source controls. Keep provider routing, admission and delivery disabled until their own gates pass.
