# Reviewed reporting-storage deployment capability

The protected storage qualifier accepts only incompatible binding schema 2. Schema 1 is held. This contract authorizes application-bounded access by a reviewed deployment; it does not establish a named Catalyst application user, token owner or provider-enforced least privilege. A null application-user response supplies none of those facts. The separate runtime-context diagnostic and all consumed observations remain unchanged.

The existing managed SDK path remains mode `user`, credential type `admin`, SDK 3.4.0, with no fallback, explicit admin initialization, credential extraction or new OAuth scope. Authentication mode/type is checked before and after normal SDK authentication. No current-user request is made by storage qualification.

## Protected binding and evidence

Retain the protected JSON/hash pair, exact Development project, source revision, control host, finite expiry, nonce and single-admitted-invocation predicate. New `capability` fields are closed and include US region/provider origin, Controller function ID, deployment identity, SDK version and exact existing authentication path. Independent protected environment values `REPORT_CONTROLLER_FUNCTION_ID` and `REPORT_DEPLOYMENT_ID` must match the capability; their configuration is not a provider identity assertion.

Both `tables.reportRuns` and `tables.eventReceipts` require numeric ID, exact name, schema/uniqueness evidence hashes, exact unique field and permitted projection hash. Numeric IDs must differ. INSERT dispatch uses numeric IDs; SELECT remains a closed name-based template whose ID/name mapping must be independently established in retained metadata. Projection hashes use canonical `{projection: sortedFieldNames}`. The source owns allowed fields; binding cannot expand them.

`evidence.ownerAuthorization`, `ownership`, `access` and `creator` require independently retained evidence digests and verification/expiry times covering the entire binding validity window. Creator evidence additionally pins independently grounded `creatorIdSha256`; it is not derived from a null current user or project `created_by`. Evidence hashes are protected owner attestations, not proof generated by this code. Missing or stale evidence holds execution.

Metadata reads establish visible metadata, not INSERT entitlement or current-token subject. Before a later qualification, the operator must establish complete ID/name/schema/unique mappings, current ownership/access provenance and expected row-creator semantics. No evidence is invented by this revision.

## Fixed operations and containment

Only fixed ReportRuns key/head SELECTs (LIMIT 2), receipt-key SELECT (LIMIT 2), immutable ReportRuns INSERT and unique admission receipt INSERT are admitted. The exact operation key owns all root/successor/receipt namespaces. Extra INSERT columns, inconsistent canonical envelopes/projections and arbitrary queries are held. Stored rows must contain the full expected projection; only named provider system fields are additionally allowed.

The revised finite maximum is seven ReportRuns reads, four ReportRuns INSERT attempts, one admission INSERT and one admission read: thirteen requests. The removed principal GET has no substitute. Concurrency outcomes retain the existing immutable successor and durable admission semantics. Ambiguous admission never grants target dispatch; no automatic mutation retry or destructive cleanup is introduced.

CRM actor authentication, contractor/Deal lineage, tenant isolation, fresh report selection, recipient attestation and delivery authority remain independent. Diagnostic success grants neither qualification nor delivery authority. This source change enables no switches and is not live storage acceptance.

## Installation and later qualification

Release packaging includes this helper in Controller's existing Analytics closure. Verify exact source revision, extracted dependency closure and auth-preserving package manifests independently of installed state. Preserve previous packages/configuration for rollback.

A later execution needs a separately reviewed fixed-target plan, fresh namespace, current protected evidence, cost/allowance verification and applicable authorization. Consumed proofs cannot be replayed. Stop on unexpected identity, permission, schema, effect, cost or ambiguous outcome; disable bindings, restore the prior package/configuration and independently verify containment. No UPDATE, DELETE, schema, permission, user or credential changes are permitted by this contract.
