# Protected read-only runtime context inspection

This diagnostic does not qualify storage, reports, delivery or routing. Safe installed package metadata proves the SDK/version and entrypoint composition, but cannot prove request-time managed user credential injection, authentication completion, socket response or fixed-principal matching. Those remain Unknown until separately observed. No raw logs are necessary.

The existing approval POST accepts only `{"profile":"report_runtime_context_v1","action":"inspect_context"}` after existing host/project/environment/shared-control authentication and bounded body collection. Its branch precedes SDK initialization and all customer stores, CRM writers and providers. Missing or invalid binding returns only fixed held observations without initializing SDK. Invalid outer authentication/configuration retains the existing generic boundary rejection; it never returns diagnostic details.

## Disabled installation and temporary binding

Default: both `REPORT_RUNTIME_CONTEXT_JSON` and `REPORT_RUNTIME_CONTEXT_SHA256` absent. Install only the reviewed exact Controller package preserving current authentication assets; keep all route/admission/bootstrap/projection/generation/send switches disabled, and consumed storage qualification variables absent. Other packages need not change for this probe. The source difference is Controller index, HTTP boundary and one new context module; its existing packaged reporting transport and SDK are reused without new dependencies or scopes.

A private exact UTF-8 JSON document has exactly: schemaVersion=2, enabled=true, environment=development, sourceRevision=exact installed candidate SHA, projectId=existing Development project, controlHost=existing authenticated host, principalSha256=SHA256 of canonical sorted-key JSON containing projectId/roleId/userId from independently verified fixed principal, verifiedAt/expiresAt=integer milliseconds with a maximum fifteen-minute window, timeoutMs=integer1..3000, nonce=fresh32lowercasehex. SHA256 pin is over actual JSON bytes. No tokens, header values or credential exports belong in this document. Parent owns binding/one invocation/disarm/readback.

Maximum one `/project-user/current` managed SDK user GET per invocation; zero table operations, record writes, PDF, WorkDrive, email or Retell. RAW SDK transport suppresses retries and owns bounded response/deadline/cancellation. Local repeated bindings are consumed before initialization. No global once-only guarantee is claimed across cold processes: without a durable write it cannot be enforced. Operator coordinates exactly one invocation and then independently verifies both binding variables absent. This is a distinct inspection, never reuse or replacement of the consumed storage operation/nonce.

Output is only the fixed fields in the module: stage, binding/source/SDK/project/environment/auth-method checks, requested user mode and Unknown credential type, authentication status, coarse principal HTTP status, identity/status/role match booleans or Unknown, and false qualification authority. No header, token, environment value, raw exception, principal identity, private body or table data is returned. Missing auth and uninitialized user credentials may intentionally remain indistinguishable; both are held pre-dispatch. Invalid pin and expired binding likewise remain safely held without revealing validation detail.

Stop on wrong source/project/principal, unknown/malformed response, unexpected effect or concrete extra charge/upgrade/limit. Do not retry, change user mode, replay storage or substitute nonce. Routine approved Zoho diagnostic traffic does not require a blanket no-cost proof. Rollback removes both inspection variables and restores the prior disabled Controller package if needed, preserving all consumed proof evidence and A2 artifacts. Recipient and number assignment source are still separately uninstalled until independently verified.

## Diagnostic-only identity model

Schema 2 rejects schema-1 and operator-bearing bindings. Its independently supplied current Catalyst principal pin replaces only the diagnostic comparison with the HMAC-derived operational actor. Configuration validation and inbound shared-header/host/project/Development/route/body authentication remain unchanged, as do all operational and storage actor checks. This does not prove an individual CRM caller identity or restore historical operator continuity.

Accept an observation only when binding, source, SDK, project, Development environment, managed authentication, HTTP 2xx, principal identity, ACTIVE status and exact App Administrator role all match. HTTP success or `ok` alone is insufficient. The module reaches `stage=complete` only after identity/status/role checks pass; qualification authority remains false. Owner security confirmation, independent patch review and extracted-package checks are required before deployment or arming. Schema-1 private kits are incompatible. Warm-only replay containment remains unchanged; there is no global one-shot guarantee.

## Bounded response failure classification

The fixed `stage` enum additionally permits `principal_stream`, `principal_size`, `principal_utf8`, `principal_json` and `principal_envelope`. They identify, respectively, response stream failure, the existing byte/chunk bound, fatal UTF-8 decoding, JSON parsing, or a missing/non-object/array `data` envelope. No response text, byte sample, header, identity, token or raw error is returned. The first classification wins; local cancellation and post-settlement teardown do not relabel a server response failure. Output remains the same fifteen fields and all failures retain false qualification authority. HTTP 2xx does not qualify identity.

The strict documented object parser and every principal/authentication condition are unchanged. The previously consumed observations remain immutable. This source prepares classification only; another live observation requires a distinct reviewed allowance and immediate disarm, never a silent retry or storage-proof replay. Existing caller allowlists must include the five reviewed stages before any approved use.
